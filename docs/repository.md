# 仓库约定

仓库只维护已验证的正式实现、当前构建和运行方法、实际验收结果。每个项目在experiments下使用一个独立目录，README说明当前行为，reports保存精简验证摘要。

## 保留内容

- RTL、引脚与时钟约束、C固件、资产源文件和仿真平台。
- 当前构建、加载和串口脚本，以及可配置的工具依赖。
- 功能、时序、CRC、SRAM、串口和实物观察的具体结果与适用范围。
- 第三方版权头、固定来源、提交号和源码哈希。

安装排障流水、试错变体、失败尝试清单、作废报告和工具包不进入正式项目。生成的build、impl和本机配置由.gitignore排除；本地练习不作为已验收项目提交。

仿真、构建和实物观察分别记录。保持数据真实：未经板上验证的配置不能继承其他位流的上板结论，未完成的边界检查应明确列为验证范围。

调整目录后核对源码、脚本相对路径、工具配置和构建结果，再清理重复目录。校验仓库结构用`python tools/validate_repo.py`。第三方源文件继续使用其原有许可证，仓库整理不改变许可。
