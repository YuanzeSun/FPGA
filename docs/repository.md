# 仓库约定

## 添加一个实验

在 `experiments/` 下建立独立目录，命名表达实验目的，例如 `led-blink`、`led-chaser`、`picorv32-uart`。从 [实验说明模板](../templates/experiment-readme.md) 开始，填写构建命令、预期行为和结果。

一个可复现的实验至少保留源码、约束、构建脚本和工具版本。有 C 固件时，也保留启动代码、链接脚本及 ROM 初始化生成方法。

## 从现有目录迁入

先复制一个简单实验，调整路径，在新位置重新构建并比较位流及报告。确认后再处理下一个，原目录等复现成功后再清理。

旧项目的脚本还有固定 Programmer 路径和 COM6 默认值，迁移时接入 `config/local.psd1` 或命令行参数。构建路径尽量相对项目根目录，避免写死用户名。

旧 README 里“未上板”等阶段性描述需要与后续结果合并。每个实验只保留一份当前说明，详细过程放进带日期的 `reports/`。旧 LED 电气约束的复核项见 [日常开发](development.md)。

## 哪些文件进入 Git

提交源码、仿真、脚本、约束、文档、依赖版本和必要的验证摘要。`build/`、下载的软件包、工具安装目录和本机配置由 `.gitignore` 排除。

需要分享位流时，使用单独的发布包，附源码提交号、工具版本、SHA256、预期行为和验证范围。仿真通过、SRAM 读回通过、串口测试通过、现场观察通过分别记录。

第三方源码固定提交号，保留原许可证及版权头，并用 `provenance.json` 记录来源和哈希。自己的代码与文档采用什么许可证，在首次对外发布前确定。

## 先做哪些自动化

先把仿真、构建和结果汇总做好。以后接 CI 时可以执行这些电脑上的检查；USB 下载留在连着开发板的电脑上单独运行。
